# 可插拔组合回测

回测属于 `src/tradeguard/backtesting`。CLI 与本机 HTTP 共用服务；控制台 `/backtests` 创建实验、管理策略启停并查看已保存报告。实验的资金、持仓和订单只存在于模拟账本，不写真实账户，也不会声称券商验证或下单成功。

## 模型和运行顺序

`BacktestConfig` 显式保存市场、币种、来源、复权、日期、固定股票池、可选基准、组合、调度、排序、资金和执行假设。信号插件负责条件，交易策略插件管理选股和目标权重，执行内核管理共享现金与订单。内置信号组合支持全部、任一、至少 N 个，以及每个信号最近 N 个观察交易日命中；未知证据不作为否定或中性分数。

1. 校验配置、已安装插件、启停和依赖；按市场/来源/复权从运行库读日线。
2. 在一次一致性读中冻结每个证券的完整区间和最多 460 根区间前日线。行情经 `BarInput` 校验；技术信号实际最多使用当前日前 400 根，与扫描保持一致。
3. 同一事务保存任务配置、插件/内核/计算依赖版本、输入清单和行情切片，任务进入 queued。
4. 每个观察日先用当日开盘尝试执行前日订单，先卖后买，同方向按代码排序；再收盘估值、执行策略调度和退出检查，生成最早下一观察日执行的委托。
5. 完成后追加报告，保存指标摘要与结果哈希；失败保存脱敏原因，不生成成功报告。图表、指标、成交和持仓均读取这份已保存报告，不重算现有行情。

日/周/月调度分别指每个观察日、每周首个观察日、每月首个观察日的收盘。退出检查每天执行。`rebalance=false` 保留已有仓位，只为新候选分配名额；`true` 按调度重新选择候选并发送目标权重。内置等权目标为 `min(max_weight, invested_fraction / max_positions)`，不因候选不足自动满仓。排序支持命中数、20 日动量和代码。命中数按策略家族计票：`box_breakout` 与 `box_high_breakout` 同属箱体家族，任一命中记 1 票，同时命中仍是 1 票。`all` / `at_least` 的门槛也按家族数。票数相同且不是按代码排序时，已命中 `box_high_breakout` 的标的排在前面。缺动量不参与动量排名。只想要收盘对最高价的确认时，组合里只放 `box_high_breakout`。

上述保留/再平衡和信号排序开关属于 `signal_portfolio`。独立交易策略有自己的选股和调仓逻辑，`uses_signals=false` 时必须显式 `combination=null`，不允许把未采用的信号附在其条件上。原有带组合的配置保持兼容。

## 经典策略与学习契约

内置共 12 个信号、4 个交易策略。新增参数化信号位于 `screening/strategies/classics.py`。`box_high_breakout` 位于 `screening/strategies/box_high_breakout.py`，不修改原来的 `box_breakout`：

| ID | 条件与退出 |
| --- | --- |
| `moving_average_cross` | 参数化 SMA/EMA 快线上穿慢线，可选长趋势过滤；下穿退出 |
| `donchian_breakout` | 收盘突破此前 N 日最高价，窗口排除当日；跌破此前 M 日最低价退出 |
| `rsi2_reversion` | Wilder 短 RSI 超跌且位于长期简单均线上方；反弹至短均线上方退出 |
| `bollinger_reversion` | 前日在下轨外、当日回到带内，可选趋势过滤；回到中轨退出 |
| `absolute_momentum` | 价格收益严格高于参数门槛；回到门槛或以下退出，收益比较使用 Decimal |
| `box_high_breakout` | 信号日前 N 根最高价/最低价形成箱体，振幅严格小于上限；收盘至少高出最高价一个幅度，且为首次突破，成交量达到均量倍数。参数默认 N=20、振幅 15%、突破 1%、量能 1.5。收盘跌破该箱体中轨退出 |

新增交易策略位于 `backtesting/classic_portfolios.py`：

- `relative_momentum`：按参数化回看/跳过窗口的收益排序，已知候选选前 N 个并按调度再平衡。未知持仓保持并预留实际预算；不足候选不放大单股目标。相对强者仍可能绝对下跌。
- `dual_momentum`：先筛价格收益严格超过门槛的风险资产，再按相对强度选择；没有合格者且证据完整时才可进入显式同币种防御标的，否则持现金。防御标的必须在股票池，数据不足不能当作市场转弱；不是原版 GEM 的总回报/无风险利率规则。
- `turtle_daily`：每日收盘检查通道与 Decimal ATR 风险单位；从实际数量增加确认批次，再按距上一确认成本的 ATR 距离申请加仓。部分成交算一批，未成交不计数，批次数/单股权重/现金均有限制。按收盘通道或只上移的 ATR 参考退出；不是原版盘中、多空、双系统或相关性限额的完整复现。

`parameters_model` 使用带中文标题、释义、范围的 Pydantic 模型；可选 `configure()` 在参数验证后设置动态预热或实例状态，可选 `validate_config()` 校验调度和股票池。三个新交易策略声明自己的预热需求；信号和交易策略共同决定清单中的实际要求，超过 400 根历史窗口明确拒绝。

`education.py` 为全部内置插件提供结构化中文说明：思路、精确入场/退出、适用研究场景、仓位、数据、合成例子、局限、原版差异、来源和固定条件。目录 API 同时提供参数 schema、默认研究值和是否使用信号。已安装外部插件可声明同结构的 `learning_guide`；没有说明时显示作者未提供，不编造规则。

平台在原有策略卡片内展开学习内容，可搜索类别并将策略带入表单。参数以中文表单呈现，JSON 放在高级区域。新报告冻结学习说明、默认值、参数定义；报告页面用本次参数解释已归档版本，说明更新不改写旧报告。旧报告缺学习存档时明确提示缺失。

年化统计按 252 个交易日计算；不足 20 个收益观察时年化收益和夏普保持未知。卖出成交盈利比例按卖出成交笔数计算，不冒充完整交易轮次的胜率。

费用、滑点、买入手数、卖出结算等待日、可选开盘涨跌幅限制均来自显式配置。成交量上限使用前一已观察日成交量，避免在开盘用当日完整成交量作仓位决策。买入必须能支付最低佣金；零目标允许清理零股；无法成交或部分成交有原因，余量不自动续单，期末未执行订单到期。止损、止盈和跟踪退出以收盘触发后次日开盘执行。期末按收盘估值，不隐式平仓，不含现金利息。

## 持久化与可复现

| 对象 | 所有权与生命周期 |
| --- | --- |
| `job_run(kind=backtest)` | 一次实验：配置、版本、清单、状态和小型结果摘要；与扫描任务按 kind 隔离 |
| `run_event` | 一个实验对应多个阶段/进度事件；控制台显示队列、回放、失败和完成 |
| `backtest_artifact` | 一个实验对应多个只追加工件；`input:证券` 保存带哈希的完整行情，`report` 保存带哈希的最终报告；不引用可变账户或行情行 |
| `strategy_plugin_state` | 插件 ID 的当前启停状态；安装与实现由 Python 包拥有，启停只影响新任务 |

表由 Alembic `b82e14d8a609` 创建。服务只插入行情和报告工件，不提供覆盖/删除接口。读取报告校验内容哈希；重放还校验冻结输入、插件、内核和 pandas/numpy/pydantic 版本。重放生成新实验并关联原实验，不读取当前行情；插件禁用不影响既有实验重放，代码版本变化则明确拒绝，需恢复旧代码。哈希用于检测内容变化，不是加密签名或完整历史代码执行环境。

HTTP 回测使用一个工作线程、最多两个运行/排队槽位；不是持久队列。进程中断不能自动续跑，超时任务经既有 stale 维护标记；冻结输入仍保留。报告可通过 CLI 或页面导出 JSON。

## 插件扩展

已安装包使用 Python entry points：

```toml
[project.entry-points."tradeguard.signals"]
my_signal = "my_package.signals:MySignal"

[project.entry-points."tradeguard.portfolio_strategies"]
my_rotation = "my_package.portfolio:MyRotation"
```

信号继承 `BaseSignalStrategy`，实现 `name/title/description/min_history/screen`，可声明 `StrategyDependency`；扫描与回测都调用同一 `screen()`。已有 `entry_signal()` 是逐时点适配器，不再维护另一套金叉/形态语义。交易策略继承 `PortfolioStrategy`，可实现 `initialize(context)`，并在 `on_close(context)` 返回 `{证券: Decimal目标权重}`；省略的证券保持原仓位，零权重表示退出。引擎检查股票池、权重、合计资金比例与最多持仓数。每次实验单独实例化，策略状态放在实例上。

可通过 `parameters_model` 声明 Pydantic 参数模型，初始化后在 `self.parameters` 读取；默认不接受额外参数。插件 `version` 默认 1；外部辅助模块或模型改变时必须递增版本。系统归档插件模块、基础信号和指标代码的哈希，但不自动追踪任意外部资源。

上下文提供当前收盘的 `current_date`、固定 `universe`、只读持仓视图、`cash/total_value`、截止当前时点的 `history(symbol,count)` 和三态 `signal(name,symbol,lookback)`。风险计算使用 `history(..., as_decimal=True)` 保留精度；`explain(symbol,evidence)` 把当前决策说明写入订单，实验的额外退出会明确覆盖该决策。数据访问必须经上下文；插件是本地受信 Python 代码，不是沙箱。HTTP 不接受 Python 源码或任意模块名。安装插件后新任务重新发现，无需修改核心；正在运行的实验使用已冻结实例和版本。

普通扫描默认使用六个主信号并遵守启停：原来的五只加上 `box_high_breakout`。CLI `scan run --strategy NAME` 可显式选择插件，依赖信号被一并校验和计算。回测在页面或 CLI 按明确组合选择，不自动套用个人纪律规则。

`backtest compare-box --source SOURCE --start YYYY-MM-DD --end YYYY-MM-DD` 只读 `daily_bar`，比较 `box_breakout` 与 `box_high_breakout`。每个信号计算其后 5/10/20 根收盘收益、其后 20 根的最大有利和最大不利偏移，以及其后 3 根收盘跌回该信号 `box_top` 的比例。可选 `--adjustment`（默认 forward）、`--market` 和重复的 `--symbol`。区间结束后最多再读 120 个自然日，用来计算前瞻指标；不写扫描或回测记录。

## 数据频率与结果限制

目前只接受 `frequency=1d`，不联网获取分钟/tick，不由日线合成细行情。后续数据准备可按需求补齐并落地 Parquet，MySQL 保存清单和任务；当前日线输入完整存入工件，已经可在行情修订后离线重放。

股票池是用户选择的固定集合，不声称重建历史全市场；当前名称只作冻结展示，不把当前行业/ST/市值当作历史事实。交易日来自所选证券缓存的并集；不能证明全市场交易所日历完整。默认发现证券间缺日就拒绝，显式允许跳过时缺日不能成交、持仓沿用旧估值并标记。区间实际观察边界与请求不同、预热不足都写入清单和报告。基准必须同市场、来源、复权且覆盖全部观察日，否则收益和超额保持未知。

前/后复权必须选择 `adjusted_research`：收益对应冻结复权价格与模拟份额，不代表原始实际成交，也不保证因子的历史可获得性。原始价必须选择 `raw_without_actions`：未处理分红、拆股等公司行为，不能解释为完整总回报。没有盘口、队列、延迟及完整交易所规则，因此报告中的净值是显式模型下的研究结果。

## 验证

`tests/test_backtesting.py` 检查共享资金、费用/滑点、时序、缺口、结算、退出、未知证据、扫描口径、插件启停和冻结重放。`tests/test_backtrader_reference.py` 用独立 Backtrader 引擎对照简单多股买卖，比较日期、数量、价格、费用和期末权益；不声称与其全部执行模型等价。

`tests/test_classic_strategies.py` 检查新策略的阈值、参数、预热、未来隔离、未知持仓、轮动排序、防御分支、Decimal ATR、实际成交批次，以及学习与参数定义的报告存档。浏览器关键流程还包括展开学习卡片、应用策略、编辑中文参数、运行独立轮动并查看归档说明。

构建后执行 `uv run pytest tests/browser_backtesting.py -q`：在独立临时 MySQL 库与本机临时 HTTP 服务中，通过 Chromium 创建双股实验、检查数据、运行、查看净值/订单/持仓/版本、导出 JSON、禁用插件后重读旧报告，以及移动端导航。不会往应用库写入验收数据。
