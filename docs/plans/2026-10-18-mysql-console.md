# MySQL、多市场控制台与真实账户

用户要求覆盖：MySQL 替换 PostgreSQL；复刻 selection 前端的扫描流程说明、每日批次、明细与图表；真实持仓与止盈止损；A股/美股隔离。无接口券商由 Agent 根据用户口述更新，长桥/富途后续通过 CLI 配置凭证拉取。

参考实现：selection/litefront，revision 6dfbe070a1d47a6869369fb2ab9430e25a542eff。保留 pathname 路由、SelectionShell、暗色 Tailwind 页面、流程展开提示、扫描列表/结果/行业和 Plotly 图表；将模拟买卖替换为真实账户只读展示与人工事实更新记录。该参考由用户明确指定。

实现与验收顺序：

1. 独立 MySQL 8.4，迁移已有 PostgreSQL 缓存/批次并核对数据；源库保持不变。
2. market/date/run ID 是扫描查询和执行边界；进度事件保存，历史每次执行可单独查看。
3. 从真实 portfolio-tracker 数据导入账户/持仓/条件单，保留各条观察时间与来源，不伪装成实时行情。没有数据的字段保持未知。
4. Agent 手工更新 CLI 建立新快照、保留旧版本，支持仓位数量/成本与已确认止盈止损的局部更新。
5. UI 复用原有页面与流程提示，显示市场、源、状态、步骤、过滤/跳过原因；长桥/富途连接状态如实呈现。
6. MySQL 集成测试、市场隔离、手工更新审计、真实缓存迁移核对、前端构建与浏览器旅程验证。

持仓数据来自已授权的真实数据源和明确用户输入，不用 selection 模拟 positions/trades 表作为真实仓。券商 token 配置和 OpenD 登录由用户后续完成，联网失败不覆盖真实缓存。现有产品不包含下单/撤单。
